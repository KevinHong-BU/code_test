# 빠른 파일 찾기 (FastFind)

Windows 드라이브 전체에서 파일·폴더를 **입력하는 즉시** 찾아 주는 프로그램입니다.
C# WinForms(.NET 8)로 만들었고, Visual Studio Community에서 바로 열어 실행할 수 있습니다.

## 왜 빠른가

일반적인 검색(탐색기 검색, `dir /s`)은 폴더를 하나씩 열어 보기 때문에 수십 초~수 분이 걸립니다.
이 프로그램은 두 단계로 나누어 이 시간을 없앴습니다.

### 1. 색인 만들기: NTFS MFT 직접 읽기 (수 초)

NTFS 드라이브에는 모든 파일의 이름·부모 폴더가 담긴 **MFT(마스터 파일 테이블)** 가 있습니다.
`FSCTL_ENUM_USN_DATA`로 MFT를 1MB 단위로 통째로 읽어 오므로, 폴더를 하나도 열지 않고
파일 백만 개 정도를 **1~3초** 안에 읽습니다. (Everything과 같은 방식, 관리자 권한 필요)

이후에는 **USN 변경 저널**을 백그라운드에서 기다리며 읽어서
파일 생성·삭제·이름 변경·이동을 **실시간으로** 색인에 반영합니다. 기다리는 동안 CPU를 쓰지 않습니다.

관리자 권한이 없거나 NTFS가 아닌 드라이브(exFAT, FAT32, ReFS 등)는 폴더를 CPU 코어 수만큼
동시에 읽는 방식(`FindFirstFileEx` + `FIND_FIRST_EX_LARGE_FETCH`)으로 색인합니다. 이때는 실시간 반영이 되지 않으므로 `F5`로 다시 색인합니다.

### 2. 검색: 이름 버퍼 하나를 SIMD로 한 번에 훑기 (수 ms)

- 모든 파일 이름을 **커다란 문자 배열 하나**에 이어 붙여 둡니다: `이름 \0 [항목 번호] 이름 \0 [항목 번호] …`
  대소문자 무시 검색용으로 대문자로 바꾼 사본도 함께 둡니다.
- 검색할 때는 파일을 하나씩 비교하지 않고, 배열 전체에 .NET 8의 **SIMD 벡터화 `IndexOf`** 를 씁니다
  (CPU가 한 번에 16~64글자씩 비교).
- 일치한 위치 바로 뒤의 `\0` 다음 두 글자에 항목 번호가 있어서 어떤 파일인지 곧바로 압니다.
- 배열을 CPU 코어 수×4 조각으로 나눠 **동시에** 훑습니다.
- 검색어 중 **가장 긴 고정 문자열**로 먼저 걸러내고, 나머지 조건(와일드카드, 제외어, 확장자 등)은 남은 후보에만 검사합니다.
- 한두 글자 검색어는 거의 모든 이름과 일치하므로 이때는 항목을 차례로 검사합니다 (이쪽이 약 2배 빠름).
- 경로 검색(`users\kim`)은 파일마다 경로를 만들지 않고, 폴더별 결과를 한 번만 계산해 재사용합니다.

### 3. 정렬: 문자열 비교 없이

- 색인이 끝나면 모든 항목을 이름순으로 한 번 정렬해 **순위 번호**를 저장해 둡니다.
- 결과가 많으면 순위 자리에 비트를 켜고 앞에서부터 읽기만 하면 정렬이 끝납니다 (O(전체/64)).
  결과가 적으면 정수 순위로 정렬합니다. 파일이 바뀌면 3초 뒤 백그라운드에서 순위를 다시 계산합니다.
- 결과 목록은 **가상 목록**이라 화면에 보이는 줄만 만듭니다. 결과가 수백만 개여도 바로 표시됩니다.

### 측정값 (참고)

| 검색어 | 결과 수 | 시간 (검색+정렬) |
|---|---:|---:|
| `zzzz_nomatch` (일치 없음) | 0 | 약 6 ms |
| `보고서 final` | 1.6만 | 약 17 ms |
| `report` | 26만 | 약 20 ms |
| `ext:pdf` | 24만 | 약 20 ms |
| `*.jpg` | 27만 | 약 30 ms |
| `e` (한 글자) | 167만 | 약 60~85 ms |
| (빈 검색어 = 전체) | 300만 | 약 40~90 ms |
| `\사진\` (경로) | 9천 | 약 55 ms |
| `regex:^IMG\d{3}` | 4만 | 약 700 ms (정규식은 느림) |

## 기능

- 입력할 때마다 바로 검색 (이전 검색은 자동 취소)
- 모든 고정 디스크(내장 HDD/SSD)를 함께 검색
- 결과 열: 이름, 경로, 크기, 수정한 날짜 (열 머리글을 누르면 정렬, 다시 누르면 반대로)
- **대상**: 전체 / 파일만 / 폴더만, **대소문자 구분** 선택
- 더블클릭·`Enter` = 열기, `Ctrl+Enter` = 파일 위치 열기, 오른쪽 클릭 메뉴
- 결과를 끌어서 탐색기나 다른 프로그램에 놓기
- 파일이 바뀌면 결과 목록이 자동으로 갱신 (선택한 항목과 스크롤 위치 유지)

## 검색어 문법

| 입력 | 의미 |
|---|---|
| `보고서 2024` | 이름에 두 단어가 **모두** 들어 있음 (공백 = AND) |
| `"my file"` | 공백이 들어간 문구 |
| `!temp` | `temp`가 들어 있지 **않음** |
| `*.pdf`, `IMG_????.jpg` | 와일드카드 (`*` = 아무 글자들, `?` = 한 글자). 이름 **전체**와 비교 |
| `ext:jpg;png` | 확장자 |
| `users\kim` | `\`가 들어가면 **전체 경로**에서 찾음 |
| `regex:^IMG_\d+` | 정규식 |

조합 예: `보고서 ext:pdf !초안`, `projects\ *.cs`, `사진\ ext:jpg;heic`

## 단축키

| 키 | 동작 |
|---|---|
| `↓` / `Enter` (검색창) | 결과 목록으로 이동 / 첫 결과 열기 |
| `Enter` / `Ctrl+Enter` | 열기 / 파일 위치 열기 |
| `Ctrl+C` / `Ctrl+Shift+C` | 전체 경로 복사 / 이름 복사 |
| `Ctrl+A` | 결과 전체 선택 |
| `Esc` | 검색창으로 이동, 검색창에서 한 번 더 누르면 검색어 지우기 |
| `Ctrl+F`, `Ctrl+L`, `F3` | 검색창으로 이동 |
| `F5` | 모든 드라이브 다시 색인 |

## 빌드 및 실행 (Visual Studio Community)

1. Visual Studio Community 2022(17.8 이상)를 설치할 때 **".NET 데스크톱 개발"** 워크로드를 선택합니다.
2. `FastFind.sln`을 엽니다.
3. 솔루션 구성을 **Release**로 바꾸고 `Ctrl+F5`(디버그 없이 실행)를 누릅니다.
   - 디버그 모드(`F5`)에서는 검색 속도가 몇 배 느립니다. 속도를 확인할 때는 Release로 실행하세요.
   - 관리자 권한이 필요하다는 창이 뜨면 **"다른 자격 증명으로 다시 시작"** 을 누르거나,
     Visual Studio를 관리자 권한으로 실행한 뒤 다시 엽니다.

실행 파일은 `FastFind\bin\Release\net8.0-windows\FastFind.exe`에 만들어집니다.
실행하면 UAC 확인 창이 뜹니다. **예**를 눌러야 MFT 방식(빠른 색인 + 실시간 반영)으로 동작합니다.
아니오를 누르거나 일반 사용자 계정이면 폴더 탐색 방식으로 색인합니다 (창 제목에 표시).

### 다른 PC에 배포할 단일 exe 만들기

```
dotnet publish FastFind\FastFind.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

`FastFind\bin\Release\net8.0-windows\win-x64\publish\FastFind.exe` 하나만 복사하면 .NET이 없는 PC에서도 실행됩니다.

### 테스트

검색 엔진 핵심 부분은 Windows API 없이 동작하므로 어느 OS에서나 테스트할 수 있습니다.
무작위 파일 트리를 만든 뒤 엔진 결과를 단순 전수 검사 결과와 비교하고, 이름 변경·이동·삭제·버퍼 압축도 확인합니다.

```
dotnet run -c Release --project FastFind.Tests            # 테스트
dotnet run -c Release --project FastFind.Tests -- --bench # 테스트 + 300만 개 성능 측정
```

```
│   ├── DirectoryScanner.cs   # 대체 방식: 병렬 폴더 탐색

│   ├── Query.cs              # 검색어 해석과 조건 (문자열, 와일드카드, 확장자, 경로, 정규식)
│   ├── SearchEngine.cs       # 병렬 SIMD 검색, 순위 기반 정렬
│   ├── ShellIcons.cs         # 확장자별 아이콘
│   └── NativeMethods.cs      # Win32 API
└── FastFind.Tests/           # 검색 엔진 테스트 + 성능 측정
```

## 참고

- 메모리: 파일 100만 개당 약 100~150MB (이름 버퍼 2벌 + 항목 정보 + 참조 번호 표 + 이름순 순위).
- 색인은 메모리에만 있고 디스크에 저장하지 않습니다. MFT 방식은 실행할 때마다 몇 초면 다시 만들어집니다.
- 검색 대상은 **고정 디스크**입니다. USB 드라이브, 네트워크 드라이브는 포함하지 않습니다.
- 크기·수정한 날짜는 화면에 보이는 줄만 그때그때 읽습니다. 그래서 이 두 열로 정렬하는 것은 결과가 20만 개 이하일 때만 하고, 그보다 많으면 이름순으로 정렬합니다.
- 프로그램이 관리자 권한으로 실행되므로, 파일을 열 때는 탐색기를 거쳐 **일반 권한**으로 엽니다.
- 정션·심볼릭 링크 폴더는 (폴더 탐색 방식에서) 따라 들어가지 않아 같은 파일이 두 번 나오지 않습니다.
